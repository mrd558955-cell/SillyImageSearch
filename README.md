# Image Search for SillyTavern

Click the images icon next to the chat box (or the wand menu, or `/imgsearch tags`) to open a picker. Tags are suggested by a small model from the latest messages, pictures come from the image boards you list in the settings, and the one you pick lands in the chat box without being sent.

## Settings

The settings are in folding sections (Setup, Picker, Saving and library, Descriptions, Picture send, Filing and looks, Advanced, Delete everything); each shows a one-line summary when closed, and the box at the top finds any setting by a word in it.

## Setup

1. In API Connections, pick a fast model that does not think (e.g. NanoGPT `deepseek/deepseek-v4.1-flash`), save it as a connection profile called `Tags`, then switch back to your main profile.
2. In the Image Search settings, choose `Tags` as the tag profile.
3. List image boards, one per line (e.g. `safebooru.org`, `danbooru.donmai.us`). Gelbooru, Danbooru, e621, Moebooru, Philomena and Shimmie sites (through their Danbooru-style address, e.g. `rule34.paheal.net`) are found on their own.
4. For the AI to see picked pictures: keep "Save picked pictures" and "Attach saved pictures" on, turn on "Send inline media" in the Chat Completion settings, and use a main model that accepts images.

Saving pictures needs `enableCorsProxy: true` in `config.yaml`, or the Cloudflare image fetcher.

Danbooru asks programs to say whose they are (a user agent with `user #<your account number>`) and puts programs that pretend to be a browser through a Cloudflare check. Put your Danbooru account (name or number) in Setup → Danbooru account: SillyTavern's server then tells Danbooru it is SillyImageSearch for that account, for searches, thumbnails, previews and saving. No API key is needed. This works in Firefox; Chrome and browsers built on it do not let pages set it, so Danbooru still blocks pictures there, and the settings say so. If a site's image server blocks its pictures (Danbooru's cdn.donmai.us sometimes asks for a Cloudflare check), Danbooru pictures are first tried from Danbooru's own site (the same file under danbooru.donmai.us/data). If that is blocked too, the picker says so instead of showing an empty grid: "Pass the check" opens the check right in the picker, and once it is passed the pictures load again by themselves ("open it in a new tab instead" is there for browsers where the check stays blank). Saving goes through SillyTavern's server, which cannot pass such a check, so saving from that site may fail until the check is lifted. With more than one image board listed, "All sites" in the picker searches them all at once; the site switches under the tag box leave some out. Typing two letters or more in the tag box suggests matching tags from the sites, favorites first.

Scroll down in a picture's preview to see all its tags: select some to add them to the search, mark them as favorites (the ★ row under the tag box), or leave out pictures that have them. The left-out list is in the settings ("Leave out pictures with these tags").

## Library

Pictures you pick are kept in the library (Library tab in the picker). Single pictures are offered to the AI through the lorebook "Image Search Pictures"; sets and sequences come only through the picture send, unless "Also offer sets and sequences" is on (then each gets one entry with a line per item). Under the library search, All / Singles / Sets / Sequences shows one kind in one tap; Order puts the pictures that fit the chat first (Best fit), the last saved first (Newest) or the last sent first (Last used); Clear all removes the search and every filter to show the whole library; the grid button switches between 2 and 3 pictures per row (kept for next time). In the library you can redo a picture's description or delete it (the file is deleted too). When a saved picture has fewer than 10 tags (paheal pictures often do), the extension looks for it on your other sites before describing it, and on Danbooru too once your Danbooru account is set (even if Danbooru is not in your sites list). First the same file (by its md5). Then its names are put into each site's own words: on Danbooru the artist is found under its Danbooru name (paheal often spells it differently), two-part names are tried in both orders (naruto_uzumaki / uzumaki_naruto) and aliases are looked up; names a site does not know are left out of the search but kept on the picture. The artist (or, without one, the rarest name) is then searched with each other name, rarest first, and the pictures of about the same shape are compared by look; a GIF is compared by 4 frames spread from start to end, so a match on any frame counts. The first picture close enough wins and the search stops. Then IQDB, a free lookalike search. Last, the vision model looks at the picture and gives a few specific tags (hair colour or style, eye colour, clothing, objects; never wide ones like 1girl or solo), each tried with the artist; after that it gives up. From a match it takes the tags of the whole group (parent and children), except for a GIF whose group has a video version: then only the video's tags. The tags found are added, so the description and filing card get them; the preview and the toast say what was searched and what matched, or link the closest pictures when nothing was close enough. "Find tags" in the preview and "Find tags for pictures with few tags" in the settings do the same by hand. For GIFs, the settings choose how many frames the vision model gets (1 to 32, spread from start to end, 3 by default), their size, and whether they go as numbered sheets instead of separate pictures. A sheet holds 4 frames (2×2) so each frame stays big; more frames make more sheets (up to 8), numbered in order across them. "Most pictures in one request" (8 by default) caps how many pictures go at once: frames are cut to fit, the second look sends fewer items per request, and a refused request is tried again with 4 frames before falling back to the first one. Lock keeps a good description: from then on Update (and "Redo all" or "Redo out-of-date descriptions") only brings the locked text up to the current description format, keeping what it says, instead of starting over; unlock to describe the picture from scratch. The settings have "Redo all descriptions" and "Delete everything".

The picture button next to Send sends your message and makes the reply come with a picture from the library: the AI picks the one that best fits what happens next, you can check it first (Send / Another / Cancel), and the reply is written to match it. Swiping keeps the same picture. The lorebook also lists the pictures that fit the current chat best (re-checked every 10 messages), so the AI can bring one in by itself.

Each described picture gets a filing card from the tag model: who is in it (gender, species, skin, hair, build, outfit, features), pose, mood, place, framing and a few story moments it could illustrate. The cards go into SillyTavern's vector search (NanoGPT embeddings by default, or the local model), so the picture button finds pictures by meaning, not shared words. Ranking is done in two steps: first by looks and keywords, then by meaning. Looks are scored by look categories you can edit under "Filing and looks → Look categories": each has a question for the AI, tags with the words that count as them, a type (same tag, ordered scale, each tag counts), what it is compared with (the character, your message, or both) and its points. Changing points costs nothing; changing tags or adding a category is filled in by "Update cards", which asks only for that category. Built in: (gender, age group from child to old, species, hair colour, build, height, skin, eyes, features, outfit; close colours like black and brown cost less), filled once by the tag model from the whole character card (and your persona, when it counts) and editable under "Characters' looks". A mismatch costs about what a match earns, and a field the picture's card does not show costs 1. The best 50 (a setting) are then ranked again by meaning. A scene cut in your message ("the next day", "hours later", "---") leaves the old scene out, and actions your message rules out ("no kissing") push pictures showing them down. Pressing the picture button first opens a small window where you choose the main focus (a chat character or you, from your persona) and whether the others may also be in the picture. The main focus counts fully and a picture without them loses 20; the others add at most 5 and are not missed when absent; left out, the AI ignores them. The choice is remembered. The best matches go to the AI, which ranks every one of them with a short reason, shown on the card ("AI #3 of 30: …"); the card also shows how each picture was found and how long each step took. Cards can be read and edited in the library preview, and the Library tab has filters for type (animated), who, pose and mood. On the picture card, "Something wrong?" cancels the send and opens that picture in the library, to fix it. The pose and mood lists are in the settings, under "Filing and looks".

Videos show up with a play badge (turn this off with "Include videos"). In the preview, set where the GIF starts (type it, or play the video and tap "Start here") and its length, check it with "Play clip", then "Make GIF"; the GIF is made on your device and used like any picture. Making GIFs and finding parts need the pictures of the video. Some browsers give them (Chrome); Firefox for Android gives black or purple pictures instead. So the extension has a built-in video reader: FFmpeg built for browsers (`@ffmpeg/core` 0.12.10, GPL), downloaded once from cdn.jsdelivr.net, or unpkg.com if that fails (32 MB), checked against its known fingerprint, kept in the browser and run on your device; nothing is uploaded. "Reading videos" in the settings chooses Automatic (the built-in reader, or the browser if it cannot be downloaded), the browser, or the built-in reader. Videos play straight from the site. If that fails, or for Danbooru (which does not let the browser play them directly), the video is downloaded once through SillyTavern (with your Danbooru account for Danbooru) and played from that copy; the download is checked to be a whole video, and fetched again if it was cut short. If it still will not play, the preview says why (a page sent instead of the video, a damaged file, or a format this browser cannot play, in which case Make GIF and Find parts still work). Versions of a picture (parent and children on the site) share one cell with a group badge. A group that hides a video or GIF behind a still cover gets a play mark on that badge: from what the search found, and by asking the site for the rest of the group as the cell scrolls into view (two at a time). "Animated only" above the grid keeps only videos, GIFs and groups with one inside; groups not checked yet stay dimmed until they are. In the group strip, animated versions are marked. Next to it, "Videos … to … s" hides videos shorter or longer than the range (either box can stay empty for no limit; kept for next time); videos whose length is not known yet stay dimmed until it is read, and one whose length cannot be read stays shown. Each video shows its length on its badge: from the site when it says (Danbooru, e621), otherwise read from the start of the file as the video scrolls into view. Saved video parts show how much of the video they cover.

A video can also become several GIFs. "Find parts" reads the whole video (a few seconds with the built-in reader) and proposes parts: each loop as 3 full turns (set with "Loop repeats in a GIF"; fewer if they do not fit the GIF length), cut so the GIF loops without a jump (a move repeated only once or twice stays part of the action; when the same loop speeds up or slows down, that is a new part, marked "the loop before, faster"); what happens between loops, cut at scene changes and split to the GIF length; quick cuts close together (a fight's climax) kept together as "Fast action"; and still stretches. No part is shorter than 1.5 s. Black stretches and fades to or from black are left out, shown striped on the timeline. "Add clip" adds the clip set above by hand. The parts show on a timeline and as cards: tap a card to play that part from the video, looping (one at a time); move its start or end by 0.1 s or 1 s, split it where it is playing, merge it with the next one or remove it. "Make GIFs" makes them (any one can be made again), and the cards then show the real GIFs and their size. Save them as a sequence (parts in order: the AI shows them one after another) or as a set (separate moments: the AI shows whichever fits); up to 8 parts. Each part goes to the vision model as a sheet of frames and is described on its own, like the items of any set or sequence (below), so a part is only given the video's tags it shows. A GIF that took its tags from a video version on another site is told those tags cover the whole video. "Finding parts" in the settings sets how easily a loop is recognised. Leaving a video, switching tabs or closing the picker stops the video and frees it, and the built-in reader closes itself after a while unused, so phones (which can only play a few videos at once) keep loading new ones. The line under the buttons says how many pictures were read and how; when the browser reads the video, a small copy of it plays in the top left corner meanwhile. Length, width and frames per second are in the settings too.

In the library preview, "Correct" lets you say what is wrong in a description: only that picture or item is rewritten, knowing its role, intensity and story line and the group's shape, following your correction over the tags; the correction is kept, so later redos (and the story step) keep it. Attach a tag when you know what confused the AI: the tag goes to "Tags that matter" with your words as its tag note. Without a tag, the correction is only recorded (Settings → Corrections without a tag).

The library preview is laid out as: the picture, the items with their role and intensity ("climax · 9", ⚠ when a deduced tag waits to be checked), a progress strip while anything runs ("Working · step 4 of 7 · Writing the story lines", also shown as "4/7" on the library cell), the buttons Use this, Correct and Redo (the rest under ⋯), then folding sections: the description (open), the tags not found, Shape and overview, How this was described (with "Your tag notes at work": where your notes were sent and what was concluded, and the raw answers), and the filing card. The tags fold at the bottom behind an arrow. What you open stays open while you switch items.

The bookmark button on a picture saves it to the library in the background without adding it to the chat, so you can keep browsing.

"Select" lets you tap pictures in story order (from different searches and from the library) and "Save as sequence". The picture send shows them one at a time, in order, as the story moves on.

Some posts have other versions on the site (parent and child posts). They share one cell in the grid, with a count in the corner. Open it to see every version; "Save set" keeps them as one library entry.

Each picture or GIF in a set or sequence (an item) gets its own description. The site's tags are for the whole group, so they are first sorted out: the vision model looks at each item without the tags and lists what it sees; each real tag goes to the items where it was seen (tags it saw that the site does not have do not matter); a tag seen in no item is looked for again in all the items, four at a time. Each item is then described with only the tags it shows and the description of the item before it (so people and things keep the same names). Then one text request reads all the descriptions in order gives the group a shape ("setup → action → pause → climax") and each item a role, main and finer (setup, build-up, action, pause, climax, aftermath or transition, like "pause, standoff"; for video parts it is told where each part is and whether it is a loop or fast action). It first rates each item's intensity from 1 to 10, as a peak of emotion and not only of action (a reconciliation hug or a tearful goodbye can be the climax of a sad scene), and decides the climax from that: the item with the highest intensity, wherever it is; an item after it showing its result or a reaction is the aftermath. Item 1 is not always the setup, roles can repeat in any order, and a loop is how a part moves, not what it is. The ratings show next to each role ("intensity 8/10"), and the story step's raw answer is in "How this was described". Each item also gets a story line on what the moment means: what was happening, what is happening, and so what ("he slurps the last noodle, so he has just finished the bowl", not "the noodles are shorter"). Every description is told that the picture comes first: tags, notes and earlier descriptions only support it, and anything the picture does not show is mentioned only as likely off screen. Its Visual line starts with how many people or characters there are, counting anyone only partly in view (an arm, a figure in the shadows): "Two people (one only partly in view): …". The vision model is told what the count tags say (1girl, 1boy, solo_focus…; for an item, the group's tags) so it looks again when they count more people than it noticed. The main person gets the full description, each other person one short sentence. People do not vanish between items: each item is told how many people the item before counted, and to count someone hidden (behind someone, off screen, in the smoke) as out of view rather than gone; the final check flags a count that drops with nothing to explain it. Descriptions, story lines and overviews never use names, for single pictures too (he, she, the blond boy in orange), even when the tags give them, so the roleplay is not handed a new name; the final check flags any that slip through. To test the intensity ratings, turn on "Intensity check (for testing)" under Descriptions → Sets and sequences, next to the story prompt: a sequence in the library then has "Check intensity", which runs only the story step on its current descriptions (one text request) and stops, and its preview shows each item's intensity as a bar with its reason, which item has the highest and which became the climax (in red when they differ), then the roles, the exact prompt sent and the answer. Roles and story lines are for sequences only: a set is versions to use on their own, so its items get no role. "Make it a set" / "Make it a sequence" (under ⋯, asks to be sure) converts a group and describes it again. Last, one request reads all the descriptions and story lines together, writes the overview and points out mistakes; an item with a wrong description is described once more, and wrong story lines are written again. Tags still found in no item (often cut off when the parts of a video were made) go to a prompt that judges whether they matter; if one does, the group is marked "Needs a look" in the library (a warning badge, and the Check filter). In the preview, the tags not found fold into one line ("Needs a look · 2 tags not found · 1 deduced"); open it and each tag is a single line with its state ("matters", "→ 2, 3 and after · note"), and tapping a tag opens only that one, with the judge's reason and these buttons: three choices: "Important" keeps it, "Not here" says it matters in general but not in this picture (it is taken out of the group, shown in red in the tag list where tapping it says why and "Put it back" restores it, it no longer counts for searches, and your reason goes to Settings → Important tags), "Doesn't matter" drops it everywhere; the item numbers place it in the items that show it, "Lasts after" also puts it in every later item (once it happened, it stays), and a note says why ("it happens off screen, because…"); a tag placed in several items gets one note box per item, or "One note" for all of them. Your choices are kept while you switch between items. Done updates only those items, keeping their descriptions (a locked one too) and telling the vision model what it missed, your note and the item's role, then writes the story lines again. Notes are saved with the tag, each with its item's role and story line, and item numbers in them are turned into roles ("item 3" becomes "the aftermath item") so they still make sense in another group (Settings → Tag notes, last 12 per tag; each can be edited, switched to "Lasts after" or removed, and you can add your own): in later groups, when nobody sees such a tag, one text request reads the story lines and your notes and places it where it most likely happens, if it is fairly sure (and in the items after, if it lasts). Those items are updated the same way (a lock is left as it is), the tags are marked (a wand badge in the library, a line on the item, a row in the panel, the Check filter "deduced"), and "Wrong" with a reason puts the items back as they were and saves the reason for next time; when a tag nobody saw looks like the cases where you said it did not apply, it can also be taken out the same way (marked, confirmed by Done, put back with Wrong); Done confirms the deductions you did not mark wrong, and each confirmed one is kept as another example. Your notes also go to the vision model when it looks again for tags nobody saw, as hints on how those tags show. Each tag in "Tags that matter", and each tag not found in a group, also gets a definition copied word for word from the wiki of the picture's site (Danbooru, e621, Moebooru and Philomena sites have one), or from Danbooru's wiki when that site has none; aliases are followed to the main tag. Settings → Important tags lists the tags that matter: tap one to see its definition (read only, with a link to the wiki and "Fetch again") and everything you wrote about it (where you placed it, corrections, confirmed or wrong deductions, and when it did not apply), editable. Definitions and always come first, before your notes: when the vision model looks again, when tags are placed from your notes, when tags not found are judged, in the updates, and at the top of each tag in the panel. Your choices are remembered ("Tags that matter" and "Tags that do not matter" in the settings, editable): next time such a tag is judged by your choice without asking, and the others are judged with your lists as examples. "Mark as fine" clears the flag without changing anything. "How this was described" in the preview shows every step: what each item was given and seen, what was found again or placed by you, what was judged and what was fixed. The steps and the prompts (story lines for sequences and for sets, judging tags not found) are under "Descriptions → Sets and sequences". In the preview each item has its own Redo, Lock and filing card, next to "Redo all"; the picture send ranks the items one by one, so the best fitting version of a set is sent (a sequence still offers its next picture). Groups saved before this keep their descriptions until they are described again; "Redo out-of-date descriptions" in the settings does all the groups with one description or no story lines.
