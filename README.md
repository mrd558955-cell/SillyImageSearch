# Image Search for SillyTavern

Click the images icon next to the chat box (or the wand menu, or `/imgsearch tags`) to open a picker. Tags are suggested by a small model from the latest messages, pictures come from the image boards you list in the settings, and the one you pick lands in the chat box without being sent.

## Settings

The settings are in folding sections (Setup, Picker, Saving and library, Descriptions, Picture send, Filing and looks, Advanced, Delete everything); each shows a one-line summary when closed, and the box at the top finds any setting by a word in it.

## Setup

1. In API Connections, pick a fast model that does not think (e.g. NanoGPT `deepseek/deepseek-v4.1-flash`), save it as a connection profile called `Tags`, then switch back to your main profile.
2. In the Image Search settings, choose `Tags` as the tag profile.
3. List image boards, one per line (e.g. `safebooru.org`, `danbooru.donmai.us`). Gelbooru, Danbooru, e621, Moebooru, Philomena and Shimmie sites (through their Danbooru-style address, e.g. `rule34.paheal.net`) are found on their own.
4. For the AI to see picked pictures: keep "Save picked pictures" and "Attach saved pictures" on, turn on "Send inline media" in the Chat Completion settings, and use a main model that accepts images.

Saving pictures needs `enableCorsProxy: true` in `config.yaml`, or the Cloudflare image fetcher.

Danbooru asks programs to say whose they are (a user agent with `user #<your account number>`) and puts programs that pretend to be a browser through a Cloudflare check. Put your Danbooru account (name or number) in Setup → Danbooru account: SillyTavern's server then tells Danbooru it is SillyImageSearch for that account, for searches, thumbnails, previews and saving. No API key is needed. This works in Firefox; Chrome does not let pages set it. If a site's image server blocks its pictures (Danbooru's cdn.donmai.us sometimes asks for a Cloudflare check), Danbooru pictures are first tried from Danbooru's own site (the same file under danbooru.donmai.us/data). If that is blocked too, the picker says so instead of showing an empty grid: "Pass the check" opens the check right in the picker, and once it is passed the pictures load again by themselves ("open it in a new tab instead" is there for browsers where the check stays blank). Saving goes through SillyTavern's server, which cannot pass such a check, so saving from that site may fail until the check is lifted. With more than one image board listed, "All sites" in the picker searches them all at once; the site switches under the tag box leave some out. Typing two letters or more in the tag box suggests matching tags from the sites, favorites first.

Scroll down in a picture's preview to see all its tags: select some to add them to the search, mark them as favorites (the ★ row under the tag box), or leave out pictures that have them. The left-out list is in the settings ("Leave out pictures with these tags").

## Library

Pictures you pick are kept in the library (Library tab in the picker) and offered to the AI through the lorebook "Image Search Pictures". Under the library search, Order puts the pictures that fit the chat first (Best fit), the last saved first (Newest) or the last sent first (Last used); Clear all removes the search and every filter to show the whole library; the grid button switches between 2 and 3 pictures per row (kept for next time). In the library you can redo a picture's description or delete it (the file is deleted too). When a saved picture has fewer than 10 tags (paheal pictures often do), the extension looks for it on your other sites before describing it, and on Danbooru too once your Danbooru account is set (even if Danbooru is not in your sites list). First the same file (by its md5). Then its names are put into each site's own words: on Danbooru the artist is found under its Danbooru name (paheal often spells it differently), two-part names are tried in both orders (naruto_uzumaki / uzumaki_naruto) and aliases are looked up; names a site does not know are left out of the search but kept on the picture. The artist (or, without one, the rarest name) is then searched with each other name, rarest first, and the pictures of about the same shape are compared by look; a GIF is compared by 4 frames spread from start to end, so a match on any frame counts. The first picture close enough wins and the search stops. Then IQDB, a free lookalike search. Last, the vision model looks at the picture and gives a few specific tags (hair colour or style, eye colour, clothing, objects; never wide ones like 1girl or solo), each tried with the artist; after that it gives up. From a match it takes the tags of the whole group (parent and children), except for a GIF whose group has a video version: then only the video's tags. The tags found are added, so the description and filing card get them; the preview and the toast say what was searched and what matched, or link the closest pictures when nothing was close enough. "Find tags" in the preview and "Find tags for pictures with few tags" in the settings do the same by hand. For GIFs, the settings choose how many frames the vision model gets (1 to 16, spread from start to end, 3 by default), their size, and whether they go as one numbered sheet instead of separate pictures. Lock keeps a good description: from then on Update (and "Redo all" or "Redo out-of-date descriptions") only brings the locked text up to the current description format, keeping what it says, instead of starting over; unlock to describe the picture from scratch. The settings have "Redo all descriptions" and "Delete everything".

The picture button next to Send sends your message and makes the reply come with a picture from the library: the AI picks the one that best fits what happens next, you can check it first (Send / Another / Cancel), and the reply is written to match it. Swiping keeps the same picture. The lorebook also lists the pictures that fit the current chat best (re-checked every 10 messages), so the AI can bring one in by itself.

Each described picture gets a filing card from the tag model: who is in it (gender, species, skin, hair, build, outfit, features), pose, mood, place, framing and a few story moments it could illustrate. The cards go into SillyTavern's vector search (NanoGPT embeddings by default, or the local model), so the picture button finds pictures by meaning, not shared words. Ranking is done in two steps: first by looks and keywords, then by meaning. Looks are scored by look categories you can edit under "Filing and looks → Look categories": each has a question for the AI, tags with the words that count as them, a type (same tag, ordered scale, each tag counts), what it is compared with (the character, your message, or both) and its points. Changing points costs nothing; changing tags or adding a category is filled in by "Update cards", which asks only for that category. Built in: (gender, age group from child to old, species, hair colour, build, height, skin, eyes, features, outfit; close colours like black and brown cost less), filled once by the tag model from the whole character card (and your persona, when it counts) and editable under "Characters' looks". A mismatch costs about what a match earns, and a field the picture's card does not show costs 1. The best 50 (a setting) are then ranked again by meaning. A scene cut in your message ("the next day", "hours later", "---") leaves the old scene out, and actions your message rules out ("no kissing") push pictures showing them down. Pressing the picture button first opens a small window where you choose the main focus (a chat character or you, from your persona) and whether the others may also be in the picture. The main focus counts fully and a picture without them loses 20; the others add at most 5 and are not missed when absent; left out, the AI ignores them. The choice is remembered. The best matches go to the AI, which ranks every one of them with a short reason, shown on the card ("AI #3 of 30: …"); the card also shows how each picture was found and how long each step took. Cards can be read and edited in the library preview, and the Library tab has filters for type (animated), who, pose and mood. On the picture card, "Something wrong?" cancels the send and opens that picture in the library, to fix it. The pose and mood lists are in the settings, under "Filing and looks".

Videos show up with a play badge (turn this off with "Include videos"). In the preview, set where the GIF starts (type it, or play the video and tap "Start here") and its length, check it with "Play clip", then "Make GIF"; the GIF is made on your device, by playing the clip and keeping its frames, and used like any picture. Danbooru videos are downloaded once through SillyTavern with your Danbooru account and played from that copy, since Danbooru does not let the browser play them directly.

A video can also become several GIFs. "Find parts" reads the whole video (faster than it plays) and proposes parts: each loop as exactly one cycle (so the GIF loops cleanly, with how many times it repeats; a loop that speeds up or slows down stays one part), what happens between loops, cut at scene changes and split to the GIF length, and still stretches. "Add clip" adds the clip set above by hand. The parts show on a timeline and as cards: tap a card to play that part from the video, looping (one at a time); move its start or end by 0.1 s or 1 s, split it where it is playing, merge it with the next one or remove it. "Make GIFs" makes them (any one can be made again), and the cards then show the real GIFs and their size. Save them as a sequence (parts in order: the AI shows them one after another) or as a set (separate moments: the AI shows whichever fits); up to 8 parts. Each part goes to the vision model as a sheet of frames, and it is told that the video's tags cover the whole video, so it only describes what each part shows. The same note is given when a GIF took its tags from a video version on another site. "Finding parts" in the settings sets how easily a loop is recognised. Length, width and frames per second are in the settings too.

The bookmark button on a picture saves it to the library in the background without adding it to the chat, so you can keep browsing.

"Select" lets you tap pictures in story order (from different searches and from the library) and "Save as sequence". The lorebook entry tells the AI to show them one at a time, in order, as the story moves on.

Some posts have other versions on the site (parent and child posts). They share one cell in the grid, with a count in the corner. Open it to see every version; "Save set" keeps them as one library entry, with one full description and what is different in each version.
